# App 统计页设计

**日期：** 2026-10-01
**状态：** 已由 TommyWu 确认
**范围：** 仅 StudyClock App 内新增统计入口与统计页；不修改通知中心 Widget 的布局、数据接口或交互。

## 目标

让用户回顾最近 7、15、30 个完整日的学习投入，比较任务分项、相邻同长度周期和当前学习目标完成情况。统计使用现有本地计时事件，不依赖网络或云端服务。

## 已确认约束

- 页面采用“分项优先”布局：先看周期总览，再按任务逐项查看统计档案。
- 周期选项固定为 7、15、30 天；窗口是最近 N 个**完整本地日**，不包含今天。
- 每个窗口均与紧邻在前的 N 个完整本地日比较。
- 统计只出现在 App 中；通知中心 Widget 保持不变。
- 目标历史尚未持久化。周期目标以任务**当前**每日目标回算，页面必须标明估算口径。

## 页面体验

### 入口与导航

- 在主仪表盘现有“历史”入口旁增加“统计”入口。
- 入口打开独立的统计页；沿用项目现有 SwiftUI 导航和关闭方式。
- 统计页不替换主计时仪表盘，也不改变历史页。
- `MenuBarView` 复用 `TimerDashboardView`。若入口直接放在共享仪表盘 toolbar，菜单栏窗口也会出现该入口；保持两处行为一致，不为统计创建另一套数据源。

### 页面结构

1. **周期选择器**：7 天、15 天、30 天；初始选择 7 天。
2. **总体摘要**：所选周期总时长、周期估算目标完成率，以及对比前一周期的时长变化和目标完成率百分点变化。
3. **分项统计档案**：按任务现有 `sortOrder` 显示每项：
   - 周期累计时长；
   - 占全部任务总投入的比例；
   - 日均投入，分母为周期的 N 个完整日，包括零投入日；
   - 周期目标、目标完成率及达标天数；
   - 对比上一周期的时长变化、目标完成率百分点变化和达标天数变化。
4. **目标估算说明**：明确说明历史周期目标按当前每日目标回算，不代表历史上当时设定的目标。

分项卡片采用紧凑进度条表达周期目标完成度，不增加占主导的大型趋势图。页面只需要周期切换、摘要与逐项比较，不加入自定义日期范围、导出或通知中心入口。

### 比较与空值呈现

- 变化量定义为：本周期时长减去上一周期时长。
- 时长环比显示绝对变化与相对百分比；上一周期时长为 0 而本期大于 0 时显示“上期无投入”，不显示无穷百分比；两期都为 0 时显示“无变化”。
- 目标完成率环比显示百分点差，达标天数显示天数差；目标百分比以各自周期目标为基数。
- 当前每日目标为 0 时显示“未设目标”，目标完成率和达标天数均不适用；不得除以 0 或显示虚假的达标状态。
- 没有任何计时历史时显示明确的空状态；有任务但周期内无投入时仍展示零值、目标和完整周期天数。周期总时长为 0 时，分项时长占比显示“—”，不计算 `0 / 0`。
- 时长采用现有中文时长格式；百分比显示为整数，避免虚假精度。
- 目标进度条视觉最多填满 100%，数值仍显示真实完成率，可超过 100%。

## 日期与目标计算口径

设 `todayStart = calendar.startOfDay(for: now)`：

- 本周期半开区间：`[todayStart - N calendar days, todayStart)`。
- 上一周期半开区间：`[todayStart - 2N calendar days, todayStart - N calendar days)`。
- 每日区间由 `Calendar` 生成，不使用固定 `N * 86_400` 秒，因此本地时区和夏令时日长变化正确。
- 每个任务每日时长沿用 `TimerSnapshot.elapsed(taskID:on:calendar:now:)` 的区间交集计算；跨午夜的连续计时按本地午夜分配到相邻日期。
- 每日目标按当前 `dailyGoalSeconds` 应用于周期内全部日期。单项周期目标为 `max(dailyGoalSeconds, 0) * N`；达标天数只统计每日目标大于 0 且该日投入达到当前目标的日期。
- 每周期目标完成率为实际投入除以周期目标。总体目标完成率只纳入有正目标的任务，实际投入与目标总量均只汇总这些任务；所有任务均无目标时显示“未设目标”。

## 数据与代码边界

- 数据源仍为 App Group 中的现有 `StudyStore`、`TimerActionRecord` 和 `TimerSnapshot`。
- 新增纯值统计结果类型与可确定性测试的聚合计算器；输入任务 ID/名称/当前每日目标、事件快照、周期、当前时间和 `Calendar`，输出总体与分项汇总。
- `TimerViewModel` 提供当前 tasks/snapshot 对应的统计查询；不让 SwiftUI 视图直接读取 SwiftData 模型或自行重建事件语义。
- 新统计页读取既有 ViewModel；不创建第二套持久化状态，不写每秒统计数据，不新增 SwiftData schema 或迁移。
- 统计只在页面打开、周期切换或共享快照/任务目标更新时重新聚合；不挂入主仪表盘的逐秒 `TimelineView` 计算。
- 本功能不改 `StudyClockWidget`、Widget DTO、Widget Timeline 策略或 `ToggleStudyTimerIntent`。

## 验证与验收

### 单元测试

1. 7 / 15 / 30 天窗口边界正确，今天被排除；上一周期与本周期相邻且不重叠。
2. 本地日历跨 DST 时仍按本地日期切片，而非固定秒数。
3. 跨午夜事件按日边界分配，三项任务的总时长和总览一致。
4. 日均分母包含零投入日；分项占比在总时长为正时与总时长一致。
5. 目标估算、达标天数、目标完成率百分点变化、零目标（含总体目标完成率排除零目标项）和历史目标变更的估算限制符合约定。
6. 上一周期无投入、两周期均无投入等零基线边界不产生无穷或 NaN 百分比。

### App 验收

- 用户可以从 App 主仪表盘打开统计页，切换 7 / 15 / 30 天，并返回主界面与历史页。
- 总体、各任务累计、占比、日均、目标完成率和相邻周期变化与同一事件快照计算结果一致。
- Widget 的布局、按钮、刷新策略及数据合同未发生变更。

## 非目标

- 不实现目标变化历史；不修改现有任务编辑或迁移 schema。
- 不增加自定义日期范围、周/月日历、导出、云同步或远端分析。
- 不把统计图表或筛选控件加入通知中心 Widget。
